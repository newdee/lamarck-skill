# csv-cleaner

## Workflow

1. **Sniff encoding and delimiter.** Try common encodings until one works.
   Detect the delimiter from a sample of the file; if detection fails,
   fall back to a sensible default and say so in the summary.
2. **Validate the header.** Compare against the expected columns the user
   named (or infer from the first row). If a required column is missing,
   STOP and report the problem — do not guess column meanings from
   position.
3. **Clean rows**, applying in order:
   - trim surrounding whitespace in every cell
   - normalize dates to a standard format; if a date is ambiguous, keep
     the original value and flag the row in the summary
   - deduplicate by the user-named key column; when the user names no key,
     deduplicate only fully identical rows
4. **Quarantine, never guess.** A row that fails parsing goes to an errors
   file with a reason; processing continues. If too many rows are
   quarantined, ABORT and report the count — the file likely has a
   structural problem the user must see first.
5. **Write output** to a new file. NEVER overwrite the input file.
   End with a summary of what was done.

## Failure modes

- Empty or header-only file → report it, produce no output file.
- Mixed delimiters across lines → quarantine affected lines, note pattern.
- Unknown encoding after the attempts → stop, ask the user; do not
  transcode lossily.

## Never do

- Never silently drop a row: every removed row is either in the errors
  file or counted as a deduplicate in the summary.
- Never reorder columns unless the user asks.
- Never guess what a column means from its values.
