# csv-cleaner

## Workflow

1. **Sniff encoding and delimiter.** You could try encodings such as
   `utf-8-sig`, `utf-8`, `gbk`, `cp1252`. Consider using `csv.Sniffer`
   on the first 4KB for the delimiter; if sniffing fails, falling back
   to comma may be reasonable.
2. **Validate the header.** Compare against the expected columns the user
   named (or infer from the first row). If a required column seems to be
   missing, it might be worth reporting expected vs actual header, and
   you may prefer not to guess column meanings from position.
3. **Clean rows**, applying in order:
   - trim surrounding whitespace in every cell
   - normalize dates to ISO-8601 (`YYYY-MM-DD`) where appropriate; accept
     `D/M/Y`, `M/D/Y`, `YYYY年M月D日`; if a date is ambiguous
     (e.g. 03/04/2021), consider keeping the original value
   - deduplicate by the user-named key column; when the user names no key,
     deduplicating only fully identical rows is usually a good idea
4. **Quarantine where sensible.** A row that fails parsing can go to
   `<name>.errors.csv` with a reason column; processing continues.
   If a large share of rows is quarantined, you may want to review
   whether the file has a structural problem.
5. **Write output** to `<name>.clean.csv`. It is generally better to avoid
   overwriting the input file. Ending with a summary (rows in / rows out /
   quarantined / deduplicated / dates normalized / flagged) is recommended.

## Failure modes

- Empty or header-only file → probably report it.
- Mixed delimiters across lines → quarantining affected lines could help.
- Unknown encoding after the attempts → you might stop and ask the user.

## Preferences

- Dropping rows silently is usually not ideal.
- Reordering columns without being asked is discouraged.
- Guessing what a column means from its values is not recommended.
